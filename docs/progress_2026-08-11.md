## Questions, Corrections & Design Decisions

### Month grouping showing entry counts instead of header counts
**Question / Observation:** The month summary rows in `my_ops_approvals` and `my_timesheets_approved` were showing inflated counts because annotating `total_hours` via a JOIN to the entries table caused `Count('opsheaderid')` to multiply rows.

**Resolution:** Added `distinct=True` to both `Count` annotations. `COUNT(DISTINCT opsheaderid)` correctly returns one count per header submission regardless of how many entries it joins to. Both views updated.

---

### Captain's visibility when a sheet is awaiting correction
**Question:** When the captain sends a sheet back for revision it disappears from their inbox entirely while they wait — is that okay?

**Decision:** Not ideal. The captain should have passive visibility into what's outstanding from their end. Added an **"Awaiting Correction"** section to the ops approval inbox — read-only, non-clickable cards with a dashed border and reduced opacity. Only renders when non-empty. Shows rejected entry count per sheet so the captain remembers what they flagged.

---

### Payroll "Paid" state visibility for crew and ops roles
**Question:** Should shifters and captains see when payroll has processed their sheets (flipping to "Paid")?

**Decision:**
- **Crew members (al=6, maintenance):** Yes — "Paid" closes the loop on their submission cycle and confirms their hours were processed. Built a dedicated paid history view.
- **Shifters (al=5) and Captains (al=4):** Deferred. Ops payroll happens at the entry level (`OperationsEntry`), not the header level, so surfacing it at the sheet level is messier. They are approvers, not payees. Revisit when ops payroll processing UI is built.

---

### Correction — ops sheet contract/account display
**Observation (two rounds):**
1. After the entry form changes, the contract dropdown only showed the code — the title was only visible after selecting. Same for accounts.
2. Then the account title was still missing from the dropdown options (only showed after selecting via the info label).

**Fixes applied:**
1. Contract dropdown options changed to `CODE — Title` format in all selects (add-row and edit-rows).
2. Account dropdown options (AJAX-populated) changed from `a.accountcode` to `` `${a.accountcode} — ${a.accounttitle}` `` in both `loadAccounts` and `loadAccountsForEntry` JS functions.

### Captain Approval Inbox — Awaiting Correction section (`timesheets/views.py`, `ops_approval_inbox.html`)

New queryset added to `ops_approval_inbox`:

```python
pending_revision_sheets = OperationsHeader.objects.filter(
    overallstatus='Revision Required', ohapprovedby_capt=request.user
).select_related(
    'shifterid', 'crewid', 'coverageid__home_shifter'
).annotate(
    entry_count=Count('operationsentry'),
    rejected_count=Count('operationsentry', filter=Q(operationsentry__linestatus='Rejected')),
).order_by('shiftdate', 'shifttype')
```

Template section added at the bottom of `ops_approval_inbox.html`:
- Wrapped in `{% if pending_revision_sheets %}` — section is invisible when nothing is pending.
- Non-clickable `<div>` cards (no `<a>` tag) with dashed border, gray background, `opacity-80`.
- Shows shifter photo, name, crew, date, rejected entry count, orange "Pending Correction" badge.
- Header note: "These sheets are with the shifter for correction. No action needed from you yet."

### My Paid Timesheets — Maintenance crew (al=6) (`timesheets/views.py`, `urls.py`, templates, `base.html`)

Payment is tracked on `MainHeader` via `paidat` (DateTimeField, nullable) and `paidby` (FK → User). A header is considered paid when `paidat__isnull=False`.

**`my_timesheets_paid`**
- Filters `MainHeader` where `employeeid=request.user` and `paidat__isnull=False`.
- Groups by `TruncMonth('paidat')` — month reflects when payroll ran, not when the sheet was submitted (more meaningful to the employee).
- Template: `my_timesheets_paid.html` — separate card per month, blue `fa-money-check-dollar` icon.

**`my_timesheets_paid_month`**
- Filters by `paidat__year` and `paidat__month`.
- Annotates `entry_count`, `total_hours`, `date_from` (Min startdate), `date_to` (Max startdate).
- Template: `my_timesheets_paid_month.html` — non-clickable cards showing pay date, work date range, hours, entry count, blue "Paid" badge, payroll processor name.

**URLs added:**
```
timesheet/paid/                     →  my_timesheets_paid
timesheet/paid/<year>/<month>/      →  my_timesheets_paid_month
```

**Nav:** "My Paid" link added for al=6 between "My Approved" and "My Rejected" with `fa-money-check-dollar` icon.

### Ops Sheet — Draft inline row editing (`timesheets/views.py`, `ops_sheet.html`)

**View (`edit_row` action extended):**

Previously only permitted in `Revision Required` status. Now allowed for both `Draft` and `Revision Required`:

```python
elif action == 'edit_row' and header.overallstatus in ('Draft', 'Revision Required'):
    if header.overallstatus == 'Revision Required':
        entry = get_object_or_404(..., linestatus='Rejected')
    else:
        entry = get_object_or_404(...)   # no linestatus filter in Draft
    # ... field updates ...
    if header.overallstatus == 'Revision Required':
        entry.linestatus = 'New'
        entry.captainnote = None
        entry.approvedby_capt = None
        entry.approvedat_capt = None
    entry.save()
```

Draft edits leave `linestatus='Draft'` and do not touch captain-related fields (they are never set at this stage).

**Template (`ops_sheet.html`):**

- All Draft display rows now have `id="row-{{ entry.opsentryid }}"`.
- Draft action cell changed from a single Delete button to **Edit + Delete** (stacked).
- After each Draft display row: a blue-tinted (`bg-blue-50`) inline edit row (`id="edit-row-..."`) and haulage row (`id="haulage-edit-..."`) — hidden by default, toggled by `openEditRow` / `closeEditRow`.
- Draft edit rows have 8 columns (no Status or Captain's Note columns). Revision Required edit rows retain 10 columns unchanged.
- The same `openEditRow`, `closeEditRow`, `saveEditRow`, `toggleHaulageEdit` JS functions serve both modes.

### Ops Sheet — Contract/Account info display in entry forms (`ops_sheet.html`)

**Contract info label:**
- A `<p id="contract-info">` (add-row) or `<p id="contract-info-edit-{id}">` (edit-rows) sits below each contract dropdown.
- Populated by `showContractInfo(contractId, infoElId)` using a `contractsData` map built from the template context at render time:
  ```js
  const contractsData = {
      {% for c in contracts %}
      "{{ c.contractid }}": { code: "...", title: "..." },
      {% endfor %}
  };
  ```
- Updates on dropdown change, on prefill apply, and on `openEditRow`.

**Account info label:**
- A `<p id="account-info">` (add-row) or `<p id="account-info-edit-{id}">` (edit-rows) sits below each account dropdown.
- Populated by `showAccountInfo(accountId, accounts, infoElId)` after AJAX resolves.
- `addRowAccounts` module-level variable keeps the loaded accounts so the account `onchange` listener can reference them without re-fetching.
- Edit-row account selects store `._accounts` on the element and register an `onchange` handler inside the AJAX callback for the same reason.

**`onEditContractChange(entryId)` helper:**
- Called by the contract dropdown `onchange` in all edit rows.
- Updates contract info label and calls `loadAccountsForEntry(entryId, null)`.

**Dropdown option text (two corrections):**
- Contract options: `{{ c.contractcode }} — {{ c.contracttitle }}` (visible while browsing, not just after select).
- Account options (AJAX): `` `${a.accountcode} — ${a.accounttitle}` `` in both `loadAccounts` and `loadAccountsForEntry`.

**Display rows:** Contract and account columns in the read-only table rows also now show code on the first line and title in smaller gray text below, for consistency.
