### 8. Footer Added to `base.html`

Added a generic footer inside `<main>`, after `{% endblock content %}` and before `</main>`, so it appears on every page in the right-side content area.

```html
<div class="pt-8 mt-auto text-center text-xs text-black">
    <p>Legal and Privacy | &copy; 2026 Wesdome Gold Mines Ltd.</p>
    <p>V1.0.4 | All Rights Reserved. Powered By Inc.</p>
</div>
```

**Key decision — why inside `<main>`:**
- The sidenav is a fixed left panel. Placing the footer outside `<main>` would span the full viewport width, causing it to sit behind or under the sidenav.
- Inside `<main>` keeps the footer scoped to the right-side content area, aligned with all page content.

**`mt-auto` note:** Has no effect here because `.main-content` is not a `flex` column container. Harmless but non-functional.

**Pending for next session:** Fix footer to the bottom of the viewport using `position: fixed`. Needs a `left` offset matching the sidenav width (`left: 200px` / `left: 280px`) so it doesn't render behind the sidenav — the same offset pattern used by `.main-content`.

## Concepts Learned Today

- **`overflow-hidden` + `rounded-full`** — `rounded-full` draws the circle shape boundary but does NOT clip content. `overflow-hidden` is required to clip the image to that shape. Both are needed for circular images.
- **`absolute` positioning with negative values** — `-bottom-12` places an element 48px *below* its positioned parent's bottom edge. Used to make the avatar straddle the banner/card boundary.
- **Django `MEDIA_URL` vs `STATIC_URL`** — static files are bundled at deploy time; media files are user-uploaded at runtime. They need separate settings and separate URL routing.
- **`request.FILES`** — file uploads arrive here (not `request.POST`). Requires `enctype="multipart/form-data"` on the HTML form or Django never receives the file.
- **`.chunks()`** — streams a file in pieces rather than loading the whole thing into memory. Important for large uploads.
- **`os.path.join` + `os.makedirs(..., exist_ok=True)`** — builds a safe cross-platform path and creates the directory if it doesn't exist, without erroring if it already does.
- **Access-level branching in views** — a single view can serve multiple roles by reading `user.access_level`, computing role-specific context, and returning the same template. The template then branches on `{% with al=... %}{% if al == X %}`.
- **Two-hop ORM query** — `User.objects.filter(supervisorid__in=mine_captains)` traverses two FK levels in one query. Django translates this to a SQL `WHERE supervisorid IN (SELECT ...)`.
- **`position: fixed` + sidenav offset** — `fixed` positions relative to the viewport, not the parent element. A fixed footer must be offset by the sidenav width (`left: 200px`) or it renders behind the sidenav. Same pattern `.main-content` uses with `ml-[200px]`.
- **`mt-auto` requires a flex parent** — `margin-top: auto` absorbs free space in a flex column container, pushing the element to the bottom. Has no effect if the parent is not `display: flex; flex-direction: column`.
