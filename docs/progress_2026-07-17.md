### 2. Crew Assignments — FieldError: `access_level` is a Python Property

After the server restarted, navigating to `/crew/assignments/` threw:

```
FieldError: Cannot resolve keyword 'access_level' into field.
```

**Root cause:** `access_level` is defined as a `@property` on the `User` model — it computes the value at runtime by traversing `roleid → accessid → accessid`. Django's ORM cannot use Python properties in `filter()` calls; it only works with real database columns.

```python
# This fails — 'access_level' is not a DB column
User.objects.filter(access_level=5)

# This works — traverses the FK chain to the actual DB field
User.objects.filter(roleid__accessid__accessid=5)
```

**Fix:** Updated all four occurrences in `users/views.py`:

| Location | Before | After |
|---|---|---|
| Shifter list (`crew_assignments`) | `access_level=5` | `roleid__accessid__accessid=5` |
| Shifter lookup (`get_object_or_404`) | `access_level=5` | `roleid__accessid__accessid=5` |
| Available employees filter | `access_level=8` | `roleid__accessid__accessid=8` |
| `add_member` guard (`get_object_or_404`) | `access_level=8` | `roleid__accessid__accessid=8` |

> **Key learning:** Whenever you need to filter users by access level in a queryset, always use `roleid__accessid__accessid=<value>`. The `access_level` property is only safe for single-object checks (e.g. `request.user.access_level == 2`).
