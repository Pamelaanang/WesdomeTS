### Design Decision — Shifter Turnover

Discussed how to handle the operational reality that shifters leave and crews need coverage in the interim. Two scenarios:

1. **Another shifter covers two crews** — operationally manageable; the covering shifter already has the right access level.
2. **A crew member steps up as acting shifter** — requires a real role/access level change; stays with sys admin.

**Decision:** Keep role and access level changes with sys admin. Introduce a lightweight `CrewCoverage` layer that the superintendent manages, recording who is covering whose crew and for how long. Coverage is transparent to the approval chain — sheets still flow through the normal captain/superintendent approval regardless of who submitted them.

### `CrewCoverage` Model (`users/models.py`)

```python
class CrewCoverage(models.Model):
    coverageid      — AutoField PK
    covering_shifter — FK → User (related_name='coverages_covering')
    home_shifter     — FK → User (related_name='coverages_home')
    startdate        — DateField
    enddate          — DateField, nullable (null = still active)
    notes            — TextField, optional
    assignedby       — FK → User (related_name='coverages_assigned')
    assignedat       — DateTimeField, auto_now_add

    db_table = 'CrewCoverage'
    ordering = ['-startdate']
```

`is_active` property on the model returns `True` if `startdate <= today` and `enddate` is null or `>= today`.

## Key Concepts Covered

- **Coverage as a separate layer** — `CrewCoverage` does not modify `CrewAssignment`. The home shifter's crew stays intact; coverage is a time-bounded pointer that says "this other shifter is acting on behalf of this crew right now."
- **Same-person guard: JS + server** — UI disables the option in the other dropdown; the view rejects it independently. Never rely on JS alone for constraints.
- **`Q()` for OR filters on nullable fields** — `Q(enddate__isnull=True) | Q(enddate__gte=today)` correctly captures both open-ended and future-terminated coverages.
- **Duplicate-check scope** — including `coverageid_id` in the duplicate filter allows one shifter to hold two sheets on the same date/shift (own crew + covered crew) without collision.
- **`SET_NULL` on operational FK** — coverage records may be deleted by admin after the fact; `SET_NULL` preserves the historical sheet without cascading deletion.
