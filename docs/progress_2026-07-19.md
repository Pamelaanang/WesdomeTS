Three new routes added:
```
operations/new/          → new_ops_sheet    (pick date/shift/crew → create header)
operations/my-sheets/    → my_ops_sheets    (shifter's sheet history)
operations/<int:pk>/     → ops_sheet        (main form with crew rows)
```

### Views written

**`new_ops_sheet`** (written by Pamela):
- Access level 5 (Shifter) only.
- GET: shows form to pick shift date, shift type, and crew.
- POST: checks for an existing header with the same shifter + date + shift type before creating — redirects to existing if found (prevents duplicates).
- Creates `OperationsHeader` and redirects to `ops_sheet`.

**`ops_sheet`**:
- Access level 5 (Shifter) only.
- Auto-submits Draft sheets older than 72 hours — sets status to `Submitted`, all entries to `linestatus='New'`. This protects payroll continuity without manual intervention.
- `hours_remaining` passed to template for a countdown banner.
- POST actions: `add_row`, `delete_row`, `submit_sheet`. POST is blocked once status leaves Draft.
- Crew rows: `CrewAssignment.objects.filter(shifter=request.user, enddate__isnull=True)`.
- Guest section: `User.objects.filter(roleid__accessid__accessid=8, isactive=True)` — any active al=8 employee regardless of crew assignment.
- Pre-fill: for each crew member, looks up their most recent `OperationsEntry` via `.filter().first()` and stores `contractid_id` / `accountid_id` in a dict keyed by `employeeid`. First-timers get empty dropdowns.
- All haulage fields (hauledto, tonnes ore/waste/skipped, longhole footage) accepted as optional via `or None`.

**`my_ops_sheets`**:
- Access level 5 (Shifter) only.
- Lists all `OperationsHeader` rows for the current shifter.
- Annotated with `entry_count` and `total_hours` via reverse FK traversal (`operationsentry`).
- Ordered by `-shiftdate`, then `shifttype`.

## Key Concepts Covered

- **`timedelta.total_seconds() / 3600`** — correct way to get total elapsed hours from a timedelta. `.seconds` only gives the seconds component within the last day, not total.
- **`.filter().first()` vs `get_object_or_404`** — use `.first()` when `None` is a valid outcome (no prior entry). `get_object_or_404` is only for cases where missing = error.
- **Reverse FK accessor in ORM annotations** — Django uses the lowercase model name (`operationsentry`) for reverse traversal when no `related_name` is set.
- **FK field name vs queryset field name** — `CrewAssignment.shifter` is the field; `shifter=request.user` is the filter. Not `shifterid`.
