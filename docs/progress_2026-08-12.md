## Questions, Corrections & Design Decisions

### Access level correction — crew bonus views
**Problem:** The previous session built all three superintendent bonus views (`superintendent_ops_members`, `superintendent_ops_member_detail`, `superintendent_ops_member_month`) under `access_level != 4` (Mine Captain) and wired the nav link into the al=4 accordion. Bonus is administered by the Superintendent (al=2), not the Mine Captain.

**Fix:**
- All three views changed to `access_level != 2`.
- Removed `ohapprovedby_capt=request.user` filter — Superintendent sees ALL completed ops entries across all captains. `ohapprovedby_capt` is the Mine Captain's approval field, not the Superintendent's.
- "Crew Bonuses" nav link moved from al=4 `menu-daily-captain` to al=2 `menu-daily` accordion.

---

### Completed sheets — 404 for Mine Captain
**Problem:** Mine Captain clicking a completed sheet from the Completed Sheets page got a 404. `review_ops_sheet` only permitted `overallstatus__in=['Submitted', 'In Progress']`.

**Fix:** Added `'Completed'` to the allowed statuses. Added `readonly = header.overallstatus == 'Completed'` flag. When readonly:
- POST is blocked server-side.
- Subtitle changes to "OPERATIONS SHEET: Completed — read-only record."
- Status banner, action column, Finish Review section, Reject modal and its JS are all hidden via `{% if not readonly %}`.

---

### Crew sheets cannot be for future dates
**Decision:** Shifters can only create crew sheets for past dates or today — a future-dated sheet is operationally meaningless.

**Implementation:** Two layers:
1. `max="{% now 'Y-m-d' %}"` on the date input in `ops_sheet.html` prevents the calendar picker from selecting a future date.
2. Server-side guard in `new_ops_sheet`: POST validates the submitted date against `today` and returns an error message if it's in the future.

---

### Shifter section type — domain gap identified
**Observation:** There are distinct types of shifters — Production, Development, Longhole, Logistics. This wasn't captured anywhere in the DB. During crew coverage, a Production shifter may cover a Longhole shift, and that needs to be reflected in the record.

**Decision:** Two new nullable fields:
- `User.shiftertype` — the shifter's home section.
- `OperationsHeader.section` — the section the sheet represents, which may differ from the submitting shifter's home section during coverage.

**Derivation logic:**
- Own crew sheet (no coverage): `section = request.user.shiftertype`
- Coverage sheet: `section = coverage.home_shifter.shiftertype`

No manual section selection by the shifter — it's always derived, so there's no opportunity to pick the wrong one.

**Crew selection note:** Crew selection (`crewid`) on the header is informational/grouping only and does not constrain the employee dropdown. The employee dropdown is based on `CrewAssignment.shifter`, not crew ID. This is intentional — crews are fluid enough that tight enforcement would add friction without real benefit. The "Start Sheet" review moment is the natural guard.

### Section derivation on sheet creation (`timesheets/views.py`, `ops_sheet.html`)

**View:** `new_ops_sheet` POST derives `section` before creating the header:
```python
if coverage_id:
    cov = active_coverages.filter(coverageid=coverage_id).first()
    section = cov.home_shifter.shiftertype if cov else None
else:
    section = request.user.shiftertype
```
`coverage_sections` dict (`{coverageid: home_shifter.shiftertype}`) passed to GET render for JS.

**Template:** Hidden `<input name="section" id="section-input">` pre-filled with `own_shiftertype`. Read-only "Section" label displays the derived value. JS listens to coverage radio changes and swaps the value:
```js
var ownSection = "{{ own_shiftertype }}";
var coverageSections = {{ coverage_sections|safe }};
radio.addEventListener('change', function() {
    var section = this.value ? (coverageSections[this.value] || '') : ownSection;
    document.getElementById('section-input').value = section;
    document.getElementById('section-display').textContent = section || '—';
});
```

**Existing sheet header:** `{% if header.section %}<span>Section: ...</span>{% endif %}` added to the metadata row. Hidden for old sheets where section is null.
