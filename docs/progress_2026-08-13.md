## Questions, Corrections & Design Decisions

### add_business_entry.html — three-mode structure
**Context:** The personal business timesheet entry page needed to handle three distinct states: draft (editing freely), revision_mode (returned for correction — only rejected entries editable), and readonly (submitted/in progress/completed — no editing).

**Implementation:** The view already returns early for `Revision Required` before reaching the readonly check, so the template only needed a top-level `{% if readonly %}...{% else %}` — the else branch covers both draft and revision_mode via the `revision_mode` context variable. No third branch needed.

- Revision mode rows: `bg-green-50` (Approved), `bg-red-50` (Rejected), `hover:bg-gray-50` (New/corrected)
- Actions: Fix+Delete on Rejected rows; "Approved" badge on Approved rows; Edit+Delete in draft
- Resubmit button disabled with `cursor-not-allowed` while `has_rejected` is true
- Inline add/edit row gets an extra empty `<td>` in revision_mode for column alignment
- Date future-check JS wrapped in `{% if not revision_mode %}` — crew members fixing rejected entries shouldn't be blocked by date validation

### Supervisor stats — dual-workflow problem
**Problem:** A Supervisor (al=3) can oversee maintenance employees (al=6, submit `MainHeader`) or business employees (al=5 Shifters, submit `BusinessHeader`) depending on their unit. Querying only one model produces wrong counts.

**Decision:** Query both models and sum. No branching logic needed — works for maintenance-only, business-only, or mixed teams, and stays correct if the org ever reorganises.

```python
direct_reports = User.objects.filter(supervisorid=user)
pending_count = (
    MainHeader.objects.filter(employeeid__in=direct_reports, overallstatus__in=['Submitted', 'In Progress']).count() +
    BusinessHeader.objects.filter(employeeid__in=direct_reports, overallstatus__in=['Submitted', 'In Progress']).count()
)
```
Same pattern for `revision_count` and `completed_month` (filtered by `completedat` not `paidat` — supervisor completes the review, not payroll).
